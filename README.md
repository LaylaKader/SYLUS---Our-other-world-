# SYLUS — A World of Our Own

**A private, persistent AI companion exploring character consistency, conversational memory, simulated emotion, and human–AI interaction.**

SYLUS is an independent full-stack application inspired by the fictional character Sylus from *Love and Deepspace*. It brings a character-centred conversational experience together with persistent chat history, owner-managed memories, relationship progression, media tools, and optional voice and proactive-contact features.

This is not a public character-chat service. The hosted instance is configured as a **single-owner private application**. Its purpose is both personal and technical: to explore what it takes to build a coherent, context-aware companion experience, and to work through the engineering challenges behind long-term conversational continuity.

> **Project status:** Active independent project / private beta. Features depend on server configuration, third-party providers, browser support, and background scheduling. Some capabilities are optional or still being refined. This README distinguishes implemented features from configuration-dependent ones.

### Short description

SYLUS is a private AI companion platform with persistent conversations, character-driven responses, saved memories, simulated emotional state, relationship progression, and personal media and voice features.

## What is implemented

### 1. Conversations and character experience

- A dedicated Sylus persona and character-guidance layer.
- Persistent conversation history stored by the backend.
- Multi-bubble assistant replies and message editing.
- Message selection and copying.
- Conversation context, local-time awareness, and fictional-world boundary instructions.
- Configurable AI model providers through server-side environment variables.

The character is a fictional persona generated by an AI model. Emotional expression and relationship progression are simulated software behaviours, not evidence of consciousness or human feelings.

### 2. Memory and relationship continuity

- A private memory area where the owner can create, review, edit, and delete saved memories.
- Memory retrieval and context injection to help responses refer to relevant information.
- Persisted simulated emotional-state data used as response-style guidance.
- A bond/relationship progression view, updated by server-side interaction logic.
- Call history and related conversation records.

Memory retrieval is not infallible. The model can overlook, misinterpret, or incorrectly use context; saved information should be reviewed and corrected when needed.

### 3. Stickers, images, and visual references

- Built-in sticker catalogue and a private Sticker Studio.
- Owner-uploaded custom stickers, with private collection management.
- Sticker references embedded in chat messages.
- Private image uploads and image attachments in conversations.
- A visual-reference library for Sylus, the owner/MC, and other named people, with reference images and notes.
- Optional AI image generation and image understanding when the required Cloudflare configuration and any applicable model terms are in place.
- Web-discovered image and link attachments where the relevant search capability is available.

### 4. Voice and proactive contact

- Read-aloud playback when the voice provider is configured.
- In-app voice-call interface using browser speech recognition and the configured voice service.
- Incoming-call invitations, which require the owner to accept before the microphone is activated.
- Optional proactive text messages and call invitations through a background scheduler.
- Push notifications when VAPID keys, device permission, and background delivery are configured.

These are not ordinary cellular phone calls. Browser support, microphone permission, notification permission, provider availability, and scheduler configuration affect whether they work. Speech recognition is browser-managed; the app sends recognised text to the backend.

### 5. Privacy and owner controls

- Owner-password sign-in and signed, HttpOnly session cookies.
- Private API endpoints protected by owner-session authentication.
- Server-side database and AI-provider credentials.
- Owner controls for memories, stickers, visual references, proactive contact, notifications, and data reset.
- Private API responses configured not to be cached.

The current hosted instance is designed for one owner. It is **not** a multi-user platform, and the owner account must never be shared as a way to let other people test the application.

## Architecture

~~~text
Browser / Installable PWA
          |
          | HTTPS
          v
     Render service
     ├── React + Vite frontend
     └── FastAPI backend
          ├── Owner authentication
          ├── Chat / persona orchestration
          ├── Memory and emotion services
          ├── Bond progression
          ├── Sticker, image, and visual-reference APIs
          ├── Voice and proactive-contact APIs
          └── PostgreSQL connection
                    |
                    v
                Neon Postgres

Optional external services:
AI model providers · Cloudflare Workers AI · ElevenLabs ·
web search · web push / background scheduler
~~~

The frontend communicates with the backend over HTTPS. The backend accesses PostgreSQL and configured external providers. Database credentials and provider API keys belong only in server-side environment variables; they must never be embedded in frontend code.

## Running the project locally

Docker Compose is the recommended starting point.

1. Install Docker with the Compose plugin.
2. Clone this repository.
3. Copy .env.compose.example to .env.
4. Replace every placeholder with a unique local secret. Do not use the hosted application's credentials.
5. Add your own model-provider API key if you want to test live AI responses. Keep it in the backend environment only.
6. Run:

   ~~~bash
   docker compose up --build
   ~~~

7. Open http://localhost:8080 and sign in using the local owner password configured in .env.

For more detail, read [the frontend guide](frontend/README.md), [the backend guide](backend/README.md), and [the Docker setup guide](docs/DOCKER_LOCAL_SETUP.md).

## Privacy, data, and access — please read

The live link is publicly reachable, but that does **not** make the private account or its contents public.

- The current deployment is configured for one owner and has no public sign-up.
- Private conversations, saved memories, bond data, call history, private stickers, uploaded images, and visual-reference collections are held in the application's private backend/database and are not intended to be accessible to visitors.
- Private API routes require a valid owner session. Do not share the owner password, bootstrap token, session secret, database URL, or provider keys.
- The public GitHub repository contains source code and documentation. It must not contain private conversation exports, personal memories, uploaded private media, production database credentials, or secret environment files.
- Messages sent to an external AI provider are processed by that provider. The application cannot promise that information sent to a provider is processed only on the SYLUS server. Check the provider's data-retention and privacy terms before using sensitive content.
- A public app URL is not a guarantee of absolute security. This project has not undergone an independent security audit. Do not treat it as a secure vault for highly sensitive information.
- The current owner authentication and data model are not a multi-tenant design. Do not create accounts for other people or share the owner login. A safe public demo would require separate user accounts and verified tenant-level data isolation first.

## Current limitations

- AI output can be inaccurate, inconsistent, or make up details. Persona instructions and memory grounding reduce some problems but do not eliminate hallucinations.
- Memory retrieval is context-based and can miss relevant memories or retrieve imperfect matches.
- Availability and behaviour depend on configured model providers, quotas, network access, and third-party service changes.
- Voice, image generation/understanding, push notifications, and proactive contact require their respective credentials, permissions, and background services.
- This is an actively developed personal project, not a production SaaS product. It has no uptime guarantee or formal security certification.
- The application is currently single-owner. Multi-user access, tenant isolation, public onboarding, and a safe external tester mode have not been implemented.
